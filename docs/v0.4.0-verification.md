## 独立审阅

独立审阅代理只读检查了 0.3.0 → 0.4.0 全部改动（49 个文件），未发现 XSS、ShareProvider 路径穿越、返回键重复处理或 Java 9+ API；Java 与 JS 的合并规则一致。据审阅修复：

1. 后台完成通知服务在 Android 14/15 被限时或拒绝启动时会导致崩溃：捕获启动异常，实现 `onTimeout` 主动停止。
2. 网络中断期间任务结束会让“生成中”状态卡住（屏幕常亮、误发完成通知）：队列为空时清除运行状态。
3. 简洁模式条目指向已删除的子图时，可能回退到根图同编号节点：改为直接忽略该条目。
4. 部分相机把照片地址同时作为返回值时，照片会被当作占位删除：识别后保留。
5. 编辑器重建时进行中的预览请求会让实时预览永久停止：重建时复位。
6. Android 13+ 默认开启的完成通知从未申请权限：首次生成时申请一次。
7. 相机打开期间旋转屏幕导致简洁模式上传丢失：选择器跨页面保留。
8. iPad 短暂断网后会整页重载编辑器、丢失撤销记录：只有编辑器页面确实失效时才重载。

另外：同时监听 IPv4/IPv6 时本机地址 `::ffff:127.0.0.1` 也视为本机；页面内下载经桥接传输的上限降到 5 MB；标签/权重修改后重新开始撤销分组；关闭隐藏调试信息时恢复原设置值；任务接口缺失时不再空指针；移除误提交的 `__pycache__`。

未改动并说明的审阅意见：口令信任 `request.remote`，若同机运行反向代理/隧道，需要在代理层自行加认证；“换种子再来一次”使用历史中保存的提示词，需要 API 账号的云端节点任务可能无法重跑；两台设备在同一时刻同步收藏时以后写入者为准。

修复后重新运行全部单元测试（Java 10 组、Node 50 项）与三项真实前端检查，均通过。
