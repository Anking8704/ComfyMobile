# ComfyMobile 安卓客户端设计（用户已确认开始开发）

## 目标与已知需求

用户使用安卓手机，希望连接本机 ComfyUI，由电脑的模型和显卡生成图片，手机接收图片，并能创建节点、连接节点、编辑工作流，而不只是运行固定模板。手机输入提示词不方便，必须专门优化。

用户已确认主要在家使用，手机和电脑连接同一 Wi-Fi，首版仅需局域网连接。用户查看了设计范围与参考图，并明确回复“ok开始做吧”。以下具体技术选择由实现方决定。

## 产品范围

交付可安装的安卓 APK、源代码、构建方法和电脑端连接说明。项目独立放在 R:/ComfyUI-aki-v3.2/ComfyMobile，不重构 ComfyUI 核心，不移动或修改模型。

主要页面为连接、工作流、提示词、任务、图库。工作流页复用电脑正在提供的 ComfyUI 前端和扩展，目标是保留已有节点编辑能力。手机提供搜索添加节点、参数编辑、连线、删除、复制、保存和导入导出工作流的操作入口。画布支持横屏、双指缩放和平移；桌面右键操作有长按或显式按钮替代。

保留完整编辑入口不等于承诺所有第三方插件已兼容手机。当前安装的自定义节点以实际验证结果列兼容清单；插件专用画布或鼠标交互遇到问题时明确说明，不静默丢失参数或替换工作流。

## 提示词编辑

选择节点内文字参数后，可以进入全屏编辑器，显示节点名称及字段名称，保存后写回原节点的原字段。支持原生文本框和标准节点字符串控件；第三方特殊编辑器只有验证可读写后才接入，不能识别时保留原编辑方式并说明原因。不能把任何文本字段都当成正向提示词。

正向和反向的区分来自用户选择的实际节点及字段，不按画布顺序自动猜测。复杂工作流允许绑定多个字段，显示明确目标。切换工作流或删除节点后禁止把旧编辑内容写入新目标；提示保留草稿并重新选择目标。

编辑器使用系统输入法，支持中文拼音、输入法提供的语音输入、选择和复制粘贴。组合输入期间不触发提交或快捷键，回车换行；“写回节点”和“生成”是分开的明确操作。软键盘出现后编辑区随窗口缩小，操作按钮仍可见；返回键先关闭键盘，不自动丢弃文本。

提供本机历史、可编辑模板及分类常用词收藏，可在光标位置插入，提供撤销/重做。选中词句后可选择加括号或调整 ComfyUI 常见权重语法，保留其余文本；此工具是可选操作，不自动重写不认识的模型提示词语法。不内置在线翻译、AI 改写或独立语音上传服务。

草稿和收藏只存手机。工作流本身按 ComfyUI 现有保存机制处理；明确区分“保存到工作流”和“保存为手机草稿”。

## 任务与图片

复用 ComfyUI 的任务提交、队列、历史和 WebSocket 进度接口，不用手机执行推理。提交应通过现有前端的工作流转换和校验路径完成，以保留扩展行为。一次点击只提交一次；失败和重连不自动重新提交。

在前台显示任务状态、可用的生成预览和结果缩略图。提供查看原图、手动保存原图到系统相册、系统分享；从系统文件选择器上传输入图片和导入 JSON。图片通过服务器返回的文件信息获取，不靠本机 Windows 路径。正确处理子目录、非 ASCII 文件名、多张结果和下载失败。

首版“图片传到手机”定义为应用内自动显示已完成结果，并由用户选择保存原图到相册。后台自动下载或常驻进度通知不在首版保证内；安卓回收应用后重新打开时从历史恢复任务状态。若用户要求锁屏自动收图，需另加后台任务设计。

## 连接与实现

建议原生 Android 外壳使用 Java 和系统 WebView，避免额外大型跨平台运行时；最低 Android 10，构建目标和依赖在实施时依据可用官方工具确定。连接页保存用户输入的 HTTP(S) 服务器地址，执行连接检查并展示可操作的失败原因。单机先支持一个当前服务器，保留最近地址。

同一 Wi-Fi 连接使用电脑局域网 IP 与 ComfyUI 实际端口（默认 8188）；电脑需要启用局域网监听，提供适配现有绘世启动方式的说明，不能盲目启动第二个占用显卡的实例。防火墙只在确有阻断且用户明确操作时处理，不自动新增广泛入站规则。

首版不包含外网连接、私有网络安装配对或公共中转，不开公网端口，不在 ComfyUI 核心增加外部联网代码。

工作流 WebView 加载用户配置的 ComfyUI 来源。外部导航交给系统浏览器。优先用来源受限的消息通信或原生发起的脚本执行；不暴露任意文件读写、任意 URL 下载等通用原生桥。服务器 URL、目标节点和字段、脚本文本传递均按对应语法编码。上传由系统文件选择器返回 URI，图片保存使用 MediaStore；不请求整个手机存储的访问权限。

标准节点字段通过当前前端公开的 app/graph/widgets 接口适配，DOM textarea/contenteditable 只做经过验证的补充入口。不修改已安装 frontend package 的打包文件。必要的移动交互和字段适配代码随 APP 注入并限定到选定的服务器，不写入模型或执行模块。若前端版本变动导致接口不可用，要显示适配失效，不静默显示保存成功。

## 本机检查结果

ComfyUI 仓库在 R:/ComfyUI-aki-v3.2/ComfyUI。requirements.txt 固定 comfyui-frontend-package 1.55.18，本机安装版本匹配。server.py 提供 /ws、/object_info、/upload/image、/view、/prompt、/queue 和 /history 等接口，前端 scripts/app.js 导出公开 app 对象。

已检测到 Node.js 与 .NET；PATH 和常见安装位置尚未检测到 Java、Gradle 或 Android SDK。实施时需下载官方构建工具到项目使用的工具目录，不改系统全局 PATH；下载量和网络可达性影响是否能当场产出 APK，不应把只有源码称为已交付 APK。

现有仓库有两处模型占位文件删除，属于用户原有状态，后续不恢复、不纳入提交。

## 验收与边界

1. 在连接页输入本机局域网地址，安卓真机能连接；电脑继续负责实际生成。
2. 在手机添加标准节点、连接或断开连线、编辑参数，保存并重新打开后内容一致。
3. 全屏编辑实际提示词字段，中文拼音输入、回车、粘贴、常用词插入和权重编辑正常，键盘不遮挡关键按钮；写回目标正确。
4. 提交现有可运行工作流，显示进度、完成结果；原图保存后可在系统相册打开。
5. 上传手机图片、导入导出工作流、断网重连不造成重复提交或数据被覆盖。
6. 针对本机实际使用的第三方节点至少选一个代表工作流验证，报告适配范围和未验证项目。
7. APK 构建成功须有构建日志及可安装文件。没有安卓真机或模拟器时，只能声明已构建和已完成的静态/主机端验证，不能声称已通过真机操作。

界面风格、项目内小型模块组织、图标等常规细节由实现方确定。首版不重写 ComfyUI 节点引擎、不安装模型、不加入云端账户或收费服务。
